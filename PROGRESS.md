# Журнал прогресса — The Quiet Place Project (клон)

Проект: полный клон thequietplaceproject.com (автор оригинала — Amitay Tweeto).
Стек: Python (Flask) + чистый HTML/CSS/JS. Без БД, без внешних зависимостей кроме Flask.

## Принцип
Полная приватность: пользовательский текст никогда не покидает браузер.
Flask отдаёт только статические страницы, POST-роутов нет.

## Заметки и решения

- Аудио: оригинал использовал композиции Marc Teichert. Внешние файлы/лицензии недоступны,
  поэтому локально синтезирован новый короткий мелодический луп и закодирован в MP3
  временно установленным генератором; в `requirements.txt` его нет и приложению он не нужен.
  Файл можно заменить на любую легально приобретённую композицию, имя оставить тем же.
- Аудио грузится только на `/quiet` и `/thoughts` (через блок `{% block audio %}` в base.html),
  запускается только после первого действия пользователя (политика браузеров),
  loop, volume 0.2, mute-переключатель в углу, при уходе со страницы останавливается
  (обработчик `pagehide`). Выбранное mute хранится не в localStorage, а отсутствует —
  чтобы не нарушать правило «никаких localStorage»; состояние живёт только в пределах страницы.
- `/dawn`: дополнительный звук генерируется Web Audio API (шум дождя + прибой), без файлов.
- `X-No-Data-Collection: true` и `Cache-Control: no-store` ставятся через `after_request`.
- Логи Werkzeug отключены (`logging` уровень WARNING + `app.logger.disabled`), тело запросов
  нигде не читается, POST-роутов нет вовсе (405 на любой POST).
- Проверка Flask через test client: `/` → 302 на `/quiet`; страницы дают 200, требуемые заголовки
  есть, `Set-Cookie` отсутствует; POST на все 4 страницы даёт 405; все указанные статики дают 200.
  Аудит шаблонов/JS: нет форм, `fetch`, `XMLHttpRequest` или `sendBeacon`; `requirements.txt`
  содержит только Flask. Контраст приглушённого текста повышен после вычисления WCAG.
- Node.js в окружении отсутствует, JS-синтаксис-проверка автоматически пропущена.
  Попытки запуска через фоновые процессы Windows test harness завершились ошибкой.
  Затем Flask запущен напрямую через `py app.py` в фоне (Terminal ID 23); HTTP-проверка
  `curl.exe http://127.0.0.1:5000/quiet` вернула 200.
- Ранее запущенный сервер разработки был остановлен перед обновлением маршрутов; многоязычная
  версия перезапущена после проверки, актуальный статус указан в записи ниже.

## Первый запуск на VPS (2026-10-14)

- `nginx -t` падал: нет `/etc/letsencrypt/live/gagroup24.ru/fullchain.pem`. Причина — DNS
  `gagroup24.ru`/`www` указывает на `31.31.197.49`, а не на `194.226.122.180`, поэтому
  Certbot не может подтвердить домен и сертификатов нет вовсе.
- На Ubuntu 26.04 Nginx ругается на `listen ... http2` (deprecated): директива в HTTPS-конфиге
  заменена на `listen 443 ssl;` + `http2 on;`.
- План: сначала A-записи DNS на сервер, потом bootstrap-конфиг, `certbot certonly`,
  HTTPS-конфиг и `certbot renew --dry-run`.
- Второй запуск на сервере (2026-10-14 05:55): `dig` по-прежнему показывает
  A `31.31.197.49` и AAAA `2a00:f940:2:2:1:1:0:298` — старые записи хостинга не удалены,
  зона ещё не указывает на `194.226.122.180`. Certbot падает с 404, потому что проверка
  уходит на чужой хост. NS домена — `ns1.hosting.reg.ru` / `ns2.hosting.reg.ru`: это DNS
  хостинга reg.ru, поэтому менять записи нужно именно в разделе управления зоной
  `gagroup24.ru` (а не в разделе DNS-серверов).
- Действие пользователя: в панели reg.ru исправить запись A (имя пустое или `@`,
  значение `194.226.122.180`), удалить A и AAAA на `31.31.197.49` и `2a00:f940:*`,
  добавить `A www 194.226.122.180`, нажать «Внести изменения зоны». Затем повторить
  `dig` и только после совпадения IP запускать certbot.
